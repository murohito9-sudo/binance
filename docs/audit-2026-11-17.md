# Audit Total Proyek — Nalar AI

Tanggal audit: 17 November 2026
Commit acuan: `8a8c994` (sebelum upgrade ini), versi aplikasi 1.2.0
Metode: pembacaan seluruh berkas sumber, penelusuran riwayat commit, eksekusi unit test, dan menjalankan server tanpa database untuk menguji jalur kesiapan.

## 1. Struktur aplikasi saat ini

```
server.js                 ~900 baris: routing, SSE chat, CRUD percakapan, unggah berkas, statis
lib/auth.js               Manus OAuth, sesi HS256, CSRF, identitas pemilik
lib/binance.js            kredensial Ed25519, tanda tangan GET /api/v3/account, ticker, klines
lib/spot-analysis.js      ATR(14), skenario stop, EMA/RSI/MACD/Bollinger
public/                   index.html, styles.css, app.js, spot.js, auth.js, nalar-logo.svg
db/schema.sql             DDL 3 tabel (diduplikasi di dalam server.js)
test/                     2 berkas unit test (8 kasus)
Dockerfile                node:22-alpine, npm ci --omit=dev, non-root
```

Entry point tunggal `server.js`. Tidak ada build step frontend, tidak ada framework UI, tidak ada ORM.

## 2. Teknologi yang digunakan

| Lapisan | Teknologi |
| --- | --- |
| Runtime | Node.js 20+ (Docker memakai 22) |
| HTTP | `node:http` tanpa framework |
| Database | MySQL 8 via `mysql2/promise` |
| Hitungan finansial | `decimal.js` |
| Frontend | HTML + CSS + JavaScript vanilla, tanpa bundler |
| Streaming | Server-Sent Events |
| Autentikasi | Manus OAuth, cookie sesi HS256, token CSRF |
| Integrasi | Binance Spot REST (read-only), layanan AI kompatibel OpenAI |

## 3. Fitur yang sudah tersedia

Percakapan AI berbahasa Indonesia; riwayat, ganti nama, hapus, dan pencarian percakapan; tiga mode jawaban (`balanced`, `concise`, `creative`); lampiran PDF/PNG/JPEG/WebP dengan validasi tanda tangan berkas; streaming SSE dengan tombol berhenti, ulangi jawaban, salin, dan umpan balik; login khusus pemilik; sinkron saldo Binance Spot baca-saja; wizard koneksi Binance; indikator teknikal EMA/RSI/MACD/Bollinger; skenario stop-loss ATR dan sizing risiko; health check; desain responsif dan aksesibel.

## 4. Fitur yang belum tersedia (terhadap master prompt)

Multi-provider AI, penggantian model dari antarmuka, pengaturan temperature/top-p/max token, manajemen system prompt berlapis, memori jangka panjang, klasifikasi dan pengambilan memori, folder percakapan, voice input/output, web search dan research mode, tool calling/agent, pengguna ganda dengan profil, halaman pengaturan, tema terang/gelap, admin dashboard, analytics penggunaan di UI, backup/export, conversation branching, projects workspace, custom persona, prompt library, knowledge base/RAG, perbandingan multi-model, conversation insights.

## 6. Kelemahan keamanan

Yang sudah baik: kredensial Binance hanya di server; tidak ada endpoint order/withdraw; sesi diverifikasi HMAC dan `appId`; CSRF wajib untuk metode non-GET; validasi tipe berkas lewat tanda tangan biner; path traversal statis ditolak; semua query memakai prepared statement.

Yang masih kurang: (a) rate limit masih in-memory, tidak berlaku lintas replika; (b) belum ada audit log peristiwa autentikasi (login sukses/gagal, rotasi sesi); (c) sesi tidak dapat dicabut per-perangkat, hanya lewat rotasi `MANUS_JWT_SECRET`; (d) CSP mengizinkan `style-src 'unsafe-inline'` karena CSS memakai atribut inline; (e) secret scanning GitHub masih nonaktif di repositori; (f) belum ada pembatasan IP untuk endpoint pemilik.

## 7. Kelemahan arsitektur

`server.js` mencampur routing, validasi, akses data, dan pemanggilan provider dalam satu berkas ~900 baris; tidak ada lapisan repository sehingga query tersebar; pemanggilan provider AI terikat langsung ke satu bentuk API; tidak ada abstraksi konfigurasi (env dibaca di banyak tempat); tidak ada test tingkat HTTP karena modul server langsung listen saat di-`require`; pencarian percakapan memakai `LIKE '%kata%'` yang tidak dapat memakai index.

## 8. Potensi peningkatan performa

Menghindari presign ulang lampiran per pesan; menambahkan index FULLTEXT untuk pencarian pesan; memisahkan `server.js` menjadi controller/service; menambahkan cache singkat untuk ticker/kline Binance yang dipakai beberapa permintaan berdekatan; memakai `SELECT` kolom minimum pada daftar percakapan (sudah dilakukan) dan pagination berbasis cursor (belum).

## 9. Rencana pengembangan

Mengikuti urutan prioritas master prompt. Fase 1 (fondasi: bug, stabilitas, struktur backend, database, keamanan) dikerjakan pada iterasi ini. Fase 2 (mesin AI inti: provider abstraction, fallback, health, konfigurasi model) dimulai pada iterasi ini dan dilanjutkan pada iterasi berikutnya bersama UI pemilihan model. Fase 3–6 (pengalaman chat lanjutan, memori/multimodal/web search, tool calling/proyek/persona, produksi) belum dimulai.

## 10. Risiko perubahan terhadap fitur lama

| Perubahan | Risiko | Mitigasi |
| --- | --- | --- |
| Jalur chat dipindah ke provider registry | Streaming bisa berhenti berbeda dari sebelumnya | Parsing SSE lama dipindah apa adanya ke `lib/providers/sse.js`, dengan 3 unit test khusus termasuk kasus aliran terputus |
| DDL dipindah ke migrasi | Tabel tidak terbentuk bila migrasi gagal | Migrasi memakai `CREATE TABLE IF NOT EXISTS`, dijalankan sebelum `dbReady = true`, dan diverifikasi 3 unit test |
| Rate limiting ditambahkan | Pengguna sah bisa terkena 429 | Batas default longgar (chat 30/menit) dan dapat diatur lewat env |
| Log terstruktur | Format log berubah | Hanya memengaruhi operasi, tidak ada kontrak API |
| `db/schema.sql` dijadikan penunjuk | Ada yang mengira skema hilang | Isi DDL dipindah utuh ke `db/migrations/001_baseline.sql` dan didokumentasikan di README |

## Bagian yang belum dapat diperiksa

Login OAuth interaktif, akun Binance live, dan deployment nyata tidak dapat diuji karena memerlukan kredensial pemilik serta platform hosting. Tidak ada instance MySQL pada lingkungan audit, sehingga migrasi diverifikasi lewat unit test dengan pool tiruan, bukan database sungguhan.
